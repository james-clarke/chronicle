Chronicle Email me

Your day, reconstructed from window titles. On your disk, nowhere else.

Chronicle watches which window is in front, groups that into tasks with a model that runs inside the app, and keeps all of it in one SQLite file in your home folder.

No account. No server. No telemetry. No cloud model. No screenshots. No keylogging.

Email me Linux (X11) today. macOS and Windows next. Ask for a build.

The day, as it happened.

Wednesday: 7h03m focused, 1h07m away, 24 switches, 12:00 is the hour that fragments. Focus events are grouped into blocks and each block is matched to a task, declared or inferred.

Every task, one card.

Open any block for its summary, every session that went into it, and where the time went. Ask about it, rename it, close it.

The week, without a spreadsheet.

This week so far: longest block 1h40m, deep work 7h58m, 66 switches, down 1h01m on last week. Tasks grouped by project with their share of the hours.

Ask your own history.

"What did I work on this morning?" Answered by the model on your machine, reading the database on your machine. The question never leaves either.

What it sees

Three focus events in, one task out. This is the whole mechanism, from a real morning.

  1. Capture. A small background process notices which window is in front and when you step away. It records the app name, the window title and the process id. That is the whole record: no keystrokes, no screenshots, no clipboard.X11 _NET_ACTIVE_WINDOW and window titles · idle from XScreenSaver
  2. Derive. A language model running inside the app groups that activity into tasks and writes a line for each.Qwen3 1.7B, Q4_K_M, via llama.cpp, in-process on the CPU · downloaded once, then never again
  3. Correct. It guesses. You fix it in bulk, and it learns from the fix. Rename, move, merge; corrections are stored and the next pass reads them.Home › Unassigned › organize folds a day's loose time into runs and pre-fills the task from past corrections
  4. Use. Standup draft each morning, a weekly report, a card per task, a chat that answers from your own history.All four read the same file

Sources

On this machine: git repos you list, Claude Code session transcripts, whether the microphone is open. Each one becomes evidence on the timeline and in the digest.

Servers you add: a ticket tracker over MCP. A ticket key in a window title becomes a task with its real name and context attached. Jira today; GitHub, Google Calendar and CalDAV presets next.

What leaves your machine

Every row is a fact about the code as it is today. It gets a new row when a new source lands.

From the developer

I built this because my standup was a guess and my timesheet was fiction. It is one person's project. There is no company behind it and no plan for one that involves your data: there is no server to send it to.

It runs on my Linux machine every day. macOS and Windows capture are written against the native APIs but not shipped yet. Task grouping is a best guess and you will correct it, which is why correcting is two clicks. The standup draft is a first pass from real events; redraft is one.

If it would be useful to you, or if it would need something else first, tell me. I read every reply.
